# 检索词生成规则

为每条知识生成 3–16 个以后提问可能使用的检索词，放在 retrievalTerms 数组中，不向正文添加小节。

- 使用代码标识（类名、表名、接口、错误码、文件名）、具体中文业务叫法、常见同义词或缩写。
- 每个词去首尾空白后为 2–64 个 Unicode 字符；不含换行或控制字符，按不区分大小写去重。
- 不写整句、提问句、解释或结论；不要使用单独的“知识”“候选”“提现”“系统”等过宽词。
- 整句判定：禁止中文 `。！？；，、` 和英文 `; ! ?`，禁止以英文句号 `.` 结尾；允许空格（`Native Memories`）和中间的点号（`file.ts`）。
- 不编造正文无法支持的标识，不输出密码、令牌或任何凭据。
- 例如候选版本冲突主题可用：["candidate_update", "VERSION_CONFLICT", "候选版本冲突", "候选并发修改"]。
- 例如 SQLite 检索词补齐主题可用：["retrieval_terms", "asset_fts", "存量检索词补齐", "backfill-terms"]。
- 反例：“应该通过候选来修订正式知识。”是整句；“数据库”过宽；这些都不能用作检索词。

存量补齐只返回本批输入中提供的 assetRef 及其 retrievalTerms，不返回标题、正文或其他改稿内容。
